OxAgent (`ox-agent`) is a globally installed Go CLI that executes the
skills, workflows, and pipelines each repository defines under `.ox-agent/`.
Project state, standards, work items, and decisions stay local and
version-controlled — the binary is the only runtime. MIT-licensed.

## Why

- **Repository-local memory** — durable state under `.ox-agent/`, not a
  service you have to run.
- **Token-efficient context** — workflows select only the context the
  current stage needs (`ox-agent context compile`).
- **Structured work items** — explicit state, progress, and lifecycle
  records instead of chat scrollback.
- **Async-chat native** — `await_input` files a durable request and leaves
  the run pending; a messenger-style host answers minutes or hours later
  and the run resumes.
- **Pluggable harnesses** — `manual`, `spawn-cli`, and `webhook` adapters;
  the packet files are the contract, transport is swappable.
- **Provenance by default** — remote skill installs pin to a resolved
  commit SHA (`remote-skills.lock`), and an append-only event journal with
  snapshots is the state spine.
- **One binary** — no npm, Bun, or project-local runtime dependency.
- **Fork-friendly** — organizations can ship a compatible asset set
  through their own fork.

## The model

```text
binary   = how execution works
skill    = what a role does
workflow = when capabilities apply
pipeline = how work is ordered
work     = what happened
harness  = who executes
```

The binary never reasons about the work — it resolves configuration,
enforces schemas, sequences stages, and journals events. The harness — any
agent that can read a file and write a file — does the reasoning.
