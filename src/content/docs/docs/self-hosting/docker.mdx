The self-host bundle lives in
[`deploy/selfhost/`](https://github.com/oxidean/oxidean/tree/main/deploy/selfhost)
of the main repository. Copy `docker-compose.yml`, `Caddyfile`, and
`.env.example` into an empty directory (plus
`docker-compose.docker-sock.yml` only if you plan to run `docker://`
Actions jobs).

## Local evaluation

<Steps>
  1. Grab the bundle files and prepare the environment: ```bash mkdir oxidean && cd oxidean # copy
  docker-compose.yml, Caddyfile, .env.example from deploy/selfhost cp .env.example .env ``` 2. Set
  `POSTGRES_PASSWORD` and `OXIDEAN_ACTIONS_SECRETS_KEY` in `.env` (`openssl rand -hex 24` / `openssl
  rand -base64 32`). For evaluation only, also set `OXIDEAN_ENV=development`. 3. ```bash docker
  compose up -d ``` 4. Open `http://localhost` — **`/setup`** walks you through the admin account
  and auth providers.
</Steps>

Tear down with `docker compose down` (add `-v` to drop the data volume).

## Production shape

<Steps>
  1. Point a DNS name at the host and keep ports 80/443 reachable. 2. Set `DOMAIN` (and the posted
  secrets) in `.env` — leave `OXIDEAN_ENV` unset (production default). 3. Bring the edge profile up
  with the stack: ```bash docker compose --profile tls up -d ``` Caddy terminates TLS for `$DOMAIN`
  with Let's Encrypt and proxies to `web:3000`. Running your own edge instead? One `reverse_proxy
  web:3000` line is the whole contract. 4. Enable CI capacity when you need it: ```bash docker
  compose --profile actions up -d ```
</Steps>

<Aside type="note">
  Prefer object storage for packages/artifacts? The `s3` profile bundles an eval-grade RustFS store;
  `OXIDEAN_STORAGE_BACKEND` and the `OXIDEAN_S3_*` set cover external endpoints too — see
  [configuration](/docs/configuration/).
</Aside>
